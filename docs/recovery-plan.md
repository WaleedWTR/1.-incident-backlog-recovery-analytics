# Backlog Recovery Plan

## 1. Establish truth

Before bulk closure or reassignment:

- remove duplicates
- identify already-restored issues
- validate pending states
- confirm ownership
- identify tickets awaiting user/supplier action
- separate true active work from administrative backlog

## 2. Prioritise

Use more than age alone:

- business impact
- priority
- SLA position
- affected users
- known workaround
- security risk
- dependency / supplier blocker
- recurrence

## 3. Work in waves

Suggested waves:

1. high-impact breached incidents
2. near-breach incidents
3. old tickets requiring ownership decisions
4. low-impact stale records
5. systemic repeat issues for problem management

## 4. Control the inflow

Backlog recovery fails if new tickets age at the same rate. Daily control must cover new demand as well as historical debt.

## 5. Exit criteria

Move from recovery to BAU when:

- oldest-age trend is stable
- breach exposure is within target
- ownership is clear
- daily inflow is controlled
- repeat causes have improvement actions
